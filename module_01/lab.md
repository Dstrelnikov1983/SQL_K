# Модуль 1. Лабораторная работа «Первые улики: фильтрация и сортировка»

> Курс «Углублённый SQL» · сквозной пример «Питание +» · PostgreSQL 16

## Легенда

Руководство «Питание +» дало аналитикам неделю, чтобы показать первые результаты.
Пока у вас нет соединений таблиц и группировок — только `WHERE`, `ORDER BY` и `LIMIT/FETCH`.
Этого достаточно, чтобы найти первые **«улики»**: строки, которые выглядят подозрительно и указывают,
где компания может терять деньги. Ваша задача — найти их, посчитать и коротко доложить.

## Цель

* закрепить построение условий `WHERE` (логика, приоритет, `IN`, `BETWEEN`, `LIKE/ILIKE`);
* научиться корректно обрабатывать `NULL` (`IS NULL`, `IS DISTINCT FROM`, `COALESCE`);
* использовать сортировку по нескольким ключам и выражениям, `FETCH FIRST … WITH TIES`, `OFFSET`;
* сформулировать первый вывод для руководства на основе данных.

## Время и формат

* **50 минут** (общая часть — 10 мин, вариант команды — 35 мин, вывод — 5 мин).
* Работа **в командах по 3–4 человека**: Команда А выполняет Вариант 1, Команда Б — Вариант 2.
  Внутри команды задания можно распределить, но вывод для руководства готовится вместе.
* Результат: файл `lab01_<команда>.sql` с запросами и комментариями + 3–5 предложений вывода.

## Ограничения

* Используйте только материал модуля: `SELECT … FROM одна_таблица WHERE … ORDER BY … LIMIT/FETCH`,
  простые арифметические выражения, `DISTINCT`, `COUNT(*)` для проверки количества строк.
* Если нужно «связать» таблицы — делайте это **вручную**: выпишите идентификаторы из первого результата
  и подставьте их в `IN (…)` второго запроса. (`JOIN` — тема модуля 3.)
* Задания со звёздочкой (★) используют готовый запрос с агрегатом `SUM` — просто выполните его.

## Вариант 1 — Команда А «Финансы и продажи»

Таблицы: `order_items`, `orders`, `customers`, `products`, `invoices`, `employees`.
Политика компании: **скидка не более 10 %**.

### А1. Скидки сверх политики

Выведите позиции заказов (`order_items`) со скидкой больше 10 %, от самых больших скидок; при равенстве — по `order_item_id`.
Затем посчитайте, сколько таких позиций, и отдельно — сколько со скидкой **20 % и выше**.

*Подсказки:* `WHERE discount_pct > 10`; для подсчёта — `SELECT COUNT(*) …`.
*Проверка:* 4365 и 1741 позиций.

### А2. Сколько это стоит в рублях

Для позиций из А1 вычислите сумму скидки **сверх** 10 % в рублях:
`quantity * unit_price * (discount_pct - 10) / 100` (округлите до копеек `ROUND(…, 2)`).
Выведите топ-20 по этой сумме, **включая строки с равным значением** на 20-м месте.

*Подсказки:* сортировка по псевдониму столбца; `FETCH FIRST 20 ROWS WITH TIES`.
*Проверка:* первая строка — позиция 9654 (заказ 2467), 52 920,00 руб.

### А3. Кто давал эти скидки

Выпишите `order_id` из первых 10 строк А2 и найдите эти заказы в таблице `orders` через `IN (…)`.
Посмотрите на столбец `employee_id`. Затем найдите этого сотрудника в `employees`.

*Вопрос:* случайность или система? Какие ещё данные понадобятся, чтобы это доказать (подумайте, что даст модуль 3–4)?

### А4. Заказы без отгрузки

1. Найдите заказы, у которых нет даты отгрузки, исключая отменённые. Отсортируйте по `required_date`.
   *Проверка:* 39 строк.
2. Какие из них уже просрочены на дату среза 31.12.2025 (`required_date < '2025-12-31'`) и всё ещё в статусе «Новый» или «В работе»?
   *Проверка:* 2 строки.
3. Контроль качества данных: есть ли заказы в статусе «Отгружен»/«Доставлен» **без** `shipped_date`? *Проверка:* 0.
4. Сколько заказов отгружено **позже** требуемой даты (`shipped_date > required_date`)? *Проверка:* 984.

*Подумайте:* почему в п. 4 не нужно отдельно исключать `shipped_date IS NULL`?

### А5. Грязные контакты клиентов

1. Выведите клиентов, у которых email отсутствует, **или** начинается/заканчивается пробелом,
   **или** записан не в нижнем регистре. Чтобы увидеть пробелы, выводите `'[' || COALESCE(email, 'NULL') || ']'`.
   *Проверка:* 53 строки.
2. Выведите клиентов без региона. *Проверка:* 3 строки.

*Вопрос:* к каким ошибкам в рассылке счетов и в отчётах по регионам это приведёт?

### А6. «Похожие» клиенты

Найдите клиентов, в названии которых встречается «ромашк», «свежест» или «колос» **в любом регистре**.
Отсортируйте по ИНН, затем по `customer_id`. Сравните ИНН и телефоны найденных строк.

*Подсказка:* `ILIKE '%ромашк%' OR …`. *Проверка:* 7 строк.
*Вопрос:* что произойдёт с отчётом «Топ-10 клиентов по выручке», если оставить данные как есть?

### А7. Цена против себестоимости

1. Найдите в `products` все виды сливочного масла (`ILIKE 'масло%'`) и сравните `base_price` и `standard_cost`.
2. Для каждого вида посчитайте позиции заказов, где **цена после скидки** `unit_price * (1 - discount_pct / 100)`
   ниже себестоимости (подставьте значение `standard_cost` из п. 1 числом).

*Проверка:* для масла 82,5 % — 552 позиции, для 72,5 % — 365.
*Вопрос:* какая доля продаж каждого вида масла убыточна? Что нужно проверить дальше?

### А8. Крупнейшие счета и постраничный вывод

1. Топ-10 счетов (`invoices`) по сумме. Чтобы порядок был однозначным, добавьте второй ключ `invoice_id`.
   *Проверка:* 1-е место — СЧ-2025-02646, 1 245 137,26.
2. Вторая «страница» рейтинга — места 11–20 (`OFFSET … FETCH NEXT …`). *Проверка:* 11-е место — СЧ-2025-03994.

### ★ А9. Keyset-пагинация

Получите следующие 10 счетов **после** счёта `invoice_id = 2881` (сумма 875 376,40) без `OFFSET`,
используя сравнение пар `(amount, invoice_id) < (…, …)`.
*Проверка:* первая строка — СЧ-2025-03817, 867 809,62.
*Вопрос:* почему направление сортировки обоих ключей должно совпадать?

### ★ А10. Цифра для руководства

Выполните готовый запрос и используйте результат в выводе:

```sql
SELECT COUNT(*)                                                         AS items,
       ROUND(SUM(quantity * unit_price * discount_pct / 100), 2)        AS discount_total_rub,
       ROUND(SUM(quantity * unit_price * (discount_pct - 10) / 100), 2) AS over_policy_rub
FROM   order_items
WHERE  discount_pct > 10;
```

## Критерии оценивания

| Критерий | Баллы |
|---|---|
| Общая часть О1–О3 выполнена, результаты совпадают с проверочными | 2 |
| Основные задания варианта выполнены (не менее 6), запросы корректны | 5 |
| Запросы оформлены: ключевые слова в верхнем регистре, выравнивание, комментарии | 1 |
| Вывод для руководства: конкретные цифры, гипотеза, следующий шаг | 2 |
| Задания ★ | +1 за каждое (не более +2) |
| **Итого** | **10 (+2)** |

Типичные причины снижения баллов: `= NULL`, `OR` без скобок, `LIMIT` без `ORDER BY`, `BETWEEN` по `timestamp`,
вывод «без цифр».
