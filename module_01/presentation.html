Где живут WHERE и ORDER BY в запросе


SELECT   order_number, order_date   -- 5
FROM     orders                     -- 1
WHERE    status = 'Отменён'         -- 2
-- GROUP BY / HAVING                -- 3, 4 (модуль 4)
ORDER BY order_date DESC            -- 6
LIMIT    10;                        -- 7

СледствиеВ WHERE нельзя сослаться на псевдоним из SELECT, а в ORDER BY — можно.

Операторы сравнения, логика, приоритет

Операторы сравнения и полуоткрытый интервал


-- Заказы декабря 2025 года
SELECT order_id,
       order_number,
       order_date,
       status
FROM   orders
WHERE  order_date >= DATE '2025-12-01'
  AND  order_date <  DATE '2026-01-01'
ORDER  BY order_date, order_id;

-- Позиции со скидкой сверх политики 10 %
SELECT COUNT(*) AS items_over_policy     -- 4365
FROM   order_items
WHERE  discount_pct > 10;
Привычка аналитикаПериоды задаём как >= начало AND < начало_следующего — работает и для date, и для timestamp.

Приоритет: NOT → AND → OR


-- Хотели: менеджер 10 И (Дистрибуция ИЛИ Тендер)
SELECT COUNT(*)            -- 690 ✘
FROM   orders
WHERE  employee_id = 10
  AND  channel = 'Дистрибуция'
   OR  channel = 'Тендер';
      

SELECT COUNT(*)            -- 651 ✔
FROM   orders
WHERE  employee_id = 10
  AND  channel IN ('Дистрибуция', 'Тендер');
Что произошлоБез скобок условие читается как (emp = 10 AND Дистрибуция) OR Тендер — +39 тендерных заказов чужих менеджеров.
ПравилоЕсть OR рядом с AND — ставим скобки. Список значений — пишем IN.

Предикаты IN, BETWEEN, LIKE

и регулярные выражения PostgreSQL

IN и BETWEEN


-- Список значений
SELECT customer_name, customer_type
FROM   customers
WHERE  customer_type IN ('Федеральная сеть',
                         'Региональная сеть');

-- Диапазон: границы ВКЛЮЧАЮТСЯ
SELECT COUNT(*)                   -- 2624
FROM   order_items
WHERE  discount_pct BETWEEN 12 AND 18;
      

-- Ловушка BETWEEN с timestamp
SELECT COUNT(*)                   -- 13 ✘
FROM   equipment_downtime
WHERE  start_time BETWEEN '2025-07-01'
                      AND '2025-07-28';

SELECT COUNT(*)                   -- 15 ✔
FROM   equipment_downtime
WHERE  start_time >= '2025-07-01'
  AND  start_time <  '2025-07-29';
Почему 13?'2025-07-28' → 2025-07-28 00:00:00: простои, начавшиеся днём 28.07, не попали.

Квиз: BETWEEN

Какое условие эквивалентно x BETWEEN 10 AND 20?

  • x > 10 AND x < 20
  • x >= 10 AND x <= 20
  • x >= 10 AND x < 20
  • Зависит от типа данных x

BETWEEN включает обе границы для любого типа. «Зависит от типа» — частая путаница: для timestamp ведёт себя так же, но граница-дата означает полночь. А BETWEEN 20 AND 10 вернёт 0 строк (есть BETWEEN SYMMETRIC).

-- Комментарии: 'акция' и 'Акция -10%'
SELECT COUNT(*) FILTER (WHERE comment LIKE  '%акция%'),  -- 234
       COUNT(*) FILTER (WHERE comment ILIKE '%акция%')   -- 452
FROM   orders;

-- Буквальный символ %
SELECT DISTINCT comment
FROM   orders
WHERE  comment LIKE '%10\%%';   -- 'Акция -10%'

Регулярные выражения: ~, ~*, SIMILAR TO


-- Телефоны строго в формате +7XXXXXXXXXX

Трёхзначная логика и её ловушки

Трёхзначная логика: TRUE, FALSE, UNKNOWN

Правило WHEREСтрока проходит, только если условие = TRUE. FALSE и UNKNOWN отбрасываются.

SELECT COUNT(*)            -- 0 (!)
FROM   customers
WHERE  region_id = NULL;

SELECT customer_id, customer_name
FROM   customers
WHERE  region_id IS NULL;   -- 19, 54, 67

Квиз: «все, кроме региона 1»

В customers 73 клиента: 13 из региона 1, у 3 регион не указан. Сколько строк вернёт WHERE region_id <> 1?

  • 60
  • 57
  • 73
  • 0

57: для трёх клиентов с NULL условие NULL <> 1 = UNKNOWN. Чтобы получить 60, пишите region_id IS DISTINCT FROM 1 или region_id <> 1 OR region_id IS NULL.

IS DISTINCT FROM, COALESCE, NULLIF


-- Позиции закупок, где приёмка не «Принято»
SELECT
  COUNT(*) FILTER (WHERE quality_status
                   <> 'Принято'),                -- 86
  COUNT(*) FILTER (WHERE quality_status
                   IS DISTINCT FROM 'Принято')   -- 94
FROM purchase_order_items;

8 позиций ещё не получены — статус NULL.


-- Подставить значение вместо NULL
SELECT customer_name,
       COALESCE(email, '(нет email)')
FROM   customers;

-- Превратить 0 в NULL → нет деления на 0
SELECT 100.0 * defect_qty
             / NULLIF(produced_qty, 0)
FROM   production_batches;

-- NULL «заражает» конкатенацию
SELECT 'тел. ' || phone,         -- NULL
       CONCAT('тел. ', phone)    -- 'тел. '
FROM   suppliers WHERE supplier_id = 12;

Ловушка NOT IN с NULL


SELECT COUNT(*)                     -- 0 (!)
FROM   customers
WHERE  region_id NOT IN (1, 2, NULL);

SELECT COUNT(*)                     -- 51
FROM   customers
WHERE  region_id NOT IN (1, 2);
Почему 0?x NOT IN (1, 2, NULL) ≡ x <> 1 AND x <> 2 AND x <> NULL. Последнее — всегда UNKNOWN, значит всё условие никогда не TRUE.
Где встретится сноваМодуль 5: NOT IN (SELECT …), где NULL «прячется» в подзапросе. Решение — NOT EXISTS.

NULL при сортировке: NULLS FIRST / LAST


SELECT supplier_name, rating
FROM   suppliers
ORDER  BY rating DESC;
-- 1-я строка: «Специи и Ко» | NULL (!)

SELECT supplier_name, rating
FROM   suppliers
ORDER  BY rating DESC NULLS LAST;
-- 1-я строка: «Сахарный комбинат Воронеж» | 4.8
СУБДNULL при ASC
PostgreSQL, Oracleв конце («больше всех»)
SQL Server, MySQLв начале («меньше всех»)
СоветВ отчётах всегда указывайте NULLS FIRST/LAST явно — переносимо и читаемо. В T-SQL такого синтаксиса нет: используют ORDER BY CASE WHEN x IS NULL THEN 1 ELSE 0 END, x.

Сортировка, TOP ↔ LIMIT, OFFSET FETCH

Топ-N и постраничный вывод

ORDER BY: ключи, выражения, COLLATE


-- Несколько ключей
SELECT customer_type, customer_name, credit_limit
FROM   customers
ORDER  BY customer_type ASC,
          credit_limit  DESC,
          customer_name;

-- По выражению / псевдониму
SELECT order_item_id,
       ROUND(quantity * unit_price
             * discount_pct / 100, 2) AS discount_rub
FROM   order_items
ORDER  BY discount_rub DESC
LIMIT  5;                  -- 1-я: 9654 | 88 200,00
      

-- Свой порядок статусов
ORDER BY CASE status
           WHEN 'Новый'     THEN 1
           WHEN 'В работе'  THEN 2
           WHEN 'Отгружен'  THEN 3
           WHEN 'Доставлен' THEN 4
           ELSE 5
         END;

-- Правила сравнения строк
ORDER BY customer_name COLLATE "C";
COLLATEБаза использует ICU-сортировку; "C" — побайтовое сравнение: «ооо "Свежесть"» уйдёт в конец списка.

WITH TIES и «случайный» порядок


-- «Топ-3 позиции по скидке»
SELECT COUNT(*)                 -- 869 (!)
FROM  (SELECT order_item_id
       FROM   order_items
       ORDER  BY discount_pct DESC
       FETCH  FIRST 3 ROWS WITH TIES) AS t;

Все 869 позиций имеют максимальную скидку 25 % — они «равны» третьей.


-- Без ORDER BY порядок НЕ гарантирован
SELECT order_number
FROM   orders
LIMIT  3;
Правило«Топ-N» без ORDER BY — это «любые N». Сегодня совпало, завтра после VACUUM или параллельного плана — другие строки.

Квиз: топ-10 счетов

Нужно показать 10 крупнейших счетов, но если 10-е и 11-е места равны по сумме — показать оба. Что выбрать?

  • LIMIT 10
  • LIMIT 11
  • ORDER BY amount DESC FETCH FIRST 10 ROWS WITH TIES
  • SELECT DISTINCT … LIMIT 10

WITH TIES добавляет все строки, равные последней по ключу сортировки. Требует ORDER BY.

Постраничный вывод: OFFSET и keyset


-- Страница 3 по 20 строк
SELECT order_id, order_number, order_date
FROM   orders
ORDER  BY order_date DESC, order_id DESC
OFFSET 40 ROWS
FETCH  NEXT 20 ROWS ONLY;
      

-- Keyset: «после последней увиденной»
SELECT order_id, order_number, order_date
FROM   orders
WHERE  (order_date, order_id)
       < (DATE '2025-12-29', 4433)
ORDER  BY order_date DESC, order_id DESC
LIMIT  20;
Проблема OFFSETПочему
Медленно на дальних страницахOFFSET 20000 читает и выбрасывает 20 000 строк (1,7 мс → 0,05 мс у keyset на 24 тыс. строк)
Дубли/пропускиновые строки «сдвигают» страницы
Прыгающие строкинеуникальный ключ сортировки (11 заказов за 31.12.2025)
РешениеУникальный «добивающий» ключ + keyset (seek) для лент и API.

Итоги: что запомнить

Фильтрация

  • NOT → AND → OR, скобки при OR
  • периоды — полуоткрытые
  • ILIKE, ~ — для «грязных» строк

NULL

  • IS NULL, не = NULL
  • <> теряет NULL → IS DISTINCT FROM
  • NOT IN (…, NULL) = 0 строк
  • COALESCE, NULLIF

Сортировка и топ-N

  • LIMIT без ORDER BY — «любые» строки
  • NULLS FIRST/LAST явно
  • FETCH … WITH TIES
  • OFFSET медленный → keyset
