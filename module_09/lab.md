## Общая часть (для обеих команд, 5 мин)

1. Подключитесь к БД, проверьте наличие личной схемы `stud_<фамилия>`. Если её нет — создайте скриптом модуля 7:

   ```sql
   SET course.stud_schema = 'stud_ivanov';   -- ваша фамилия
   -- и выполнить файл module_07/scripts/00_personal_schema.sql целиком
   ```

   В личной схеме есть копии таблиц `pitanie` с теми же именами — поэтому исходные таблицы **всегда** указывайте с префиксом `pitanie.`.

2. В начале скрипта:

   ```sql
   SET search_path TO stud_ivanov, pitanie, public;
   ```

3. **Правила.**
   * Читаем данные напрямую из `pitanie.*`, объекты создаём **только** в `stud_<фамилия>` (пишите полное имя: `stud_ivanov.v_...`).
   * Каждый объект снабжайте комментарием `COMMENT ON VIEW/FUNCTION ... IS '...'`.
   * Скрипт должен выполняться повторно без ошибок: `CREATE OR REPLACE`, `DROP ... IF EXISTS`.
   * Дата среза для дебиторской задолженности — **31.12.2025** (конец периода данных).
   * Выручка строки: `quantity * unit_price * (1 - discount_pct / 100)`; отменённые заказы (`status = 'Отменён'`) не учитываем.

4. Проверка объекта — всегда запрос к нему с контрольной цифрой из задания. Не совпало — ищите ошибку в соединениях (дубли при JOIN «один ко многим» — самая частая).

## Вариант 1 — Команда А «Финансы и продажи»

> **Контекст.** Финансовый директор Белова М. С. жалуется: каждый отчёт по продажам аналитики собирают заново, цифры в разных отчётах не сходятся. Ваша задача — создать единый «слой» представлений и функций для продаж и дебиторки и с его помощью подготовить для неё короткую записку: где компания теряет деньги.

### Задание А1. Представление `v_sales_lines` (базовая витрина продаж)

Создайте представление «одна строка = одна позиция заказа» (без отменённых заказов) со столбцами:
`order_item_id, order_id, order_date, customer_id, employee_id, channel, product_id, category_id, top_category_id, quantity, unit_price, discount_pct, standard_cost, gross_amount, discount_amount, net_amount, cost_amount, margin`.

*Подсказки:*
1. Соедините `orders` → `order_items` → `products` → `product_categories`.
2. `top_category_id` — это `parent_category_id` категории товара.
3. `discount_amount = quantity * unit_price * discount_pct / 100`; `cost_amount = quantity * standard_cost`; `margin = net_amount − cost_amount`.
4. Округлите денежные столбцы до 2 знаков (`ROUND(..., 2)`).

**Проверка:** `SELECT COUNT(*), SUM(net_amount), SUM(margin) FROM stud_ivanov.v_sales_lines;` → **16 923** строки, выручка ≈ **829,1 млн**, маржа ≈ **229,2 млн**.

*Дополнительно:* найдите товары, у которых есть строки с отрицательной маржой. Сколько их и сколько денег потеряно? *(Должно получиться 2 товара.)*

### Задание А2. Представление `v_receivables` (дебиторка на 31.12.2025)

Одна строка на клиента: `customer_id, customer_name, credit_limit, payment_terms_days, invoiced, paid, debt, overdue_debt, overdue_invoices, over_limit`.

*Подсказки:*
1. Внутри представления используйте CTE `inv`: счёт + клиент (через `orders`) + оплачено по счёту на дату среза (коррелированный подзапрос к `payments` с `COALESCE(..., 0)`).
2. Почему нельзя просто `JOIN payments` и `SUM(i.amount)`? Проверьте на одном счёте с двумя оплатами.
3. Просроченный долг — по счетам с `due_date < DATE '2025-12-31'` (`SUM(...) FILTER (WHERE ...)`).
4. `over_limit` — логический столбец `debt > credit_limit`.

**Проверка:** общий долг всех клиентов ≈ **55,9 млн**; клиентов с превышением лимита — **1**. Кто это, какой у него долг и лимит, сколько просроченных счетов?

### Задание А3. CTE-отчёт «План / факт 2025»

Одним запросом из цепочки CTE (`fact` → `plan` → `pf`) постройте выполнение плана 2025 г. по месяцам и категориям верхнего уровня. Факт берите из `v_sales_lines`.

*Подсказки:* план — `sales_plan` (категории верхнего уровня); соединяйте по месяцу и `top_category_id` (`LEFT JOIN` от плана, чтобы не потерять месяцы без продаж); выведите только месяцы с выполнением ниже 85 %.

**Проверка:** должно получиться **6 строк**. Какой категории и какого периода они касаются? Посчитайте отдельным запросом суммарный недобор в рублях за этот период *(≈ 19,5 млн)*. Обсудите в команде: это проблема продаж или проблема плана?

### Задание А4. Рекурсивный CTE «Вся команда коммерческого директора»

Коммерческий директор Громов А. И. (`employee_id = 3`) хочет видеть всех своих подчинённых **на всех уровнях** с их результатами.

### Задание А5. Табличная функция `fn_customer_debt(p_date date)`

### Задание А6. Табличная функция `fn_manager_discount_violations(p_from, p_to, p_limit)`

## Вариант 2 — Команда Б «Производство и закупки»

> **Контекст.** Директор по производству Лебедев А. Н. хочет ежедневно видеть «здоровье» производства без обращения к аналитикам. Ваша задача — создать витрины по качеству, закупкам и расходу сырья и с их помощью оценить в рублях потери производства.

### Задание Б1. Представление `v_batch_quality`

Одна строка = партия: `batch_id, batch_number, production_date, prod_year, line_id, line_name, shift, operator_id, operator_name, product_id, product_name, planned_qty, produced_qty, defect_qty, defect_pct, plan_pct, defect_cost`.

*Подсказки:*
1. `production_batches` + `production_lines` + `products` + `LEFT JOIN employees` (оператор может быть не указан).
2. `defect_pct = 100.0 * defect_qty / NULLIF(produced_qty, 0)`; `plan_pct` — аналогично к `planned_qty`.
3. `defect_cost = defect_qty * standard_cost`.

**Проверка:** **6 062** партии, стоимость брака ≈ **13,76 млн**. Сгруппируйте по линии и смене — какая пара выделяется и во сколько раз?

### Задание Б2. Представление `v_supplier_price_benchmark`

Для каждой пары «материал — поставщик»: `material_id, material_name, supplier_id, supplier_name, qty, amount, avg_price, best_price, overprice_pct, overpay, qty_share_pct, suppliers_cnt`.

*Подсказки:*
1. CTE: средневзвешенная цена `SUM(quantity * unit_price) / SUM(quantity)` по `purchase_order_items` + `purchase_orders`.
2. `best_price` — минимальная средняя цена по материалу среди поставщиков: `MIN(avg_price) OVER (PARTITION BY material_id)` (оконные функции — модуль 8).
3. `overpay = qty * (avg_price − best_price)`; `qty_share_pct` — доля объёма поставщика в закупках материала.

**Проверка:** по материалам с `suppliers_cnt > 1` отсортируйте по `overpay`. Какой поставщик занимает 5 из 6 верхних строк? Его суммарная переплата ≈ **3,93 млн**. Какая у него доля в закупках сахара?

### Задание Б3. Материализованное представление `mv_material_overuse`

Перерасход сырья к нормам рецептуры по `line_id, shift, material_id`: `norm_qty, fact_qty, overuse_pct, overuse_cost`.

*Подсказки:*
1. Три CTE: `norm` (`recipes.qty_per_unit * produced_qty`, суммируем по линии/смене/материалу), `fact` (`material_consumption` по тем же ключам), `price` (средняя закупочная цена материала).
2. **Не соединяйте** `recipes` и `material_consumption` в одном `FROM` до группировки — получите размножение строк. Агрегируйте по отдельности, потом соединяйте.
3. `overuse_pct = 100 * (fact / norm − 1)`, `overuse_cost = (fact − norm) * avg_price`.
4. Создайте уникальный индекс и выполните `REFRESH MATERIALIZED VIEW CONCURRENTLY`.

**Проверка:** **84** строки; строк с перерасходом больше 3 % — **5**. Какие линии и материалы? Каков «нормальный фон» перерасхода у остальных?

### Задание Б4. CTE-цепочка «Стоимость потерь производства 2025»

Постройте одним запросом таблицу по линиям за 2025 г.:
* `defects` — стоимость брака (из `v_batch_quality`);
* `line_margin` — средняя маржа единицы продукции линии `(base_price − standard_cost)`, взвешенная по выпуску;
* `downtime` — часы закрытых простоев (`end_time IS NOT NULL`);
* `downtime_cost` — упущенная маржа: `часы × capacity_per_hour × маржа единицы`;
* `writeoffs` — списания сырья за 2025 г. (общезаводская строка, `UNION ALL`).

**Проверка:** **6 строк** (5 линий + списания). Линия-лидер по потерям — ≈ **26,8 млн**, из них простои — 590 ч. Обсудите: насколько корректна оценка «часы × мощность» (линия не всегда работает 24/7)? Как её уточнить?

### Задание Б5. Рекурсивный CTE «Производственный персонал»

Найдите всех подчинённых директора по производству (`employee_id = 4`) на всех уровнях и для операторов — брак по сменам (через `v_batch_quality.operator_id`).

### Задание Б6. Табличная функция `fn_line_report(p_line, p_from, p_to)`

Помесячный отчёт по линии: `month, batches, planned_qty, produced_qty, defect_pct, plan_pct, downtime_hours`. В отчёте должны быть **все** месяцы периода (календарь через `generate_series` или рекурсивный CTE + `LEFT JOIN`).

**Проверка:**

### Задание Б7. Табличная функция `fn_supplier_overpay(p_material)`

Для заданного материала — поставщики с `qty, avg_price, best_price, overpay`, по убыванию переплаты.

**Проверка:** `fn_supplier_overpay(4)` (сахар-песок) → **3 строки**, лучшая цена **63,85** руб./кг, у самого дорогого — **80,52**. Вызовите функцию для **всех** материалов через `CROSS JOIN LATERAL` и найдите топ-5 переплат.
Кто из закупщиков (`purchase_orders.employee_id`) чаще всего размещал заказы на сахар у самого дорогого поставщика?

### Задание Б8. «Вывод для руководства»

Соберите (CTE + `UNION ALL`) таблицу «Находка — млн руб.»: переплата дорогому поставщику; брак «проблемной» смены; перерасход сырья на «проблемной» линии; списания сырья с истёкшим сроком (какой материал списывается больше всего?). Напишите 4–6 предложений директору по производству.
