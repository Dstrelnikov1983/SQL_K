## Часть 1. Блок DO и переменные

### Шаг 1. Первый анонимный блок

```sql
DO $$
BEGIN
    RAISE NOTICE 'Привет, «Питание +»! Сейчас %', now()::date;
END
$$;
```

`$$ ... $$` — строковая константа в «долларовых кавычках»: внутри можно писать одинарные кавычки без экранирования. `%` в `RAISE` — место подстановки следующего аргумента; знак процента в тексте пишется как `%%`.

### Шаг 2. Переменные, константы и `SELECT ... INTO`

Выполните блок 2.1 из `examples.sql`.

```sql
DO $$
DECLARE
    c_policy   CONSTANT numeric := 10;
    v_orders   integer;
    v_revenue  numeric(14,2) := 0;
    v_from     date := DATE '2025-01-01';
BEGIN
    SELECT COUNT(DISTINCT o.order_id),
           SUM(oi.quantity * oi.unit_price * (1 - oi.discount_pct / 100))
    INTO   v_orders, v_revenue
    FROM   pitanie.orders      AS o
    JOIN   pitanie.order_items AS oi ON oi.order_id = o.order_id
    WHERE  o.status <> 'Отменён' AND o.order_date >= v_from;

    RAISE NOTICE 'Заказов: %, выручка % млн', v_orders, round(v_revenue / 1e6, 1);
END
$$;
```

**Ожидаемый вывод:** `Заказов с 01.01.2025: 2240, выручка 445.1 млн, лимит скидки 10 %`

> **Подумайте.** Что будет, если попытаться присвоить значение константе `c_policy := 15`? (Ошибка компиляции блока: `variable "c_policy" is declared CONSTANT`.)

### Шаг 3. `%TYPE`, `%ROWTYPE`, `RECORD`

Блоки 2.2 и 2.3:

| Объявление | Что означает | Когда удобно |
|---|---|---|
| `v_name pitanie.customers.customer_name%TYPE` | тип «как у столбца» | при изменении типа столбца код не ломается |
| `v_cust pitanie.customers%ROWTYPE` | вся строка таблицы | `SELECT * INTO v_cust`, затем `v_cust.credit_limit` |
| `r record` | строка любой структуры | результат произвольного запроса, переменная цикла |

**Ожидаемо:**
```text
NOTICE: Клиент: ООО "Торговый дом Вектор", лимит 3000000.00, отсрочка 30 дн., менеджер id 10
NOTICE: Линия 3 — кисломолочная: партий 1254, брак 92795 шт.
```

### Шаг 4. `INTO STRICT`

| Запрос вернул | `SELECT ... INTO` | `SELECT ... INTO STRICT` |
|---|---|---|
| 0 строк | переменные = NULL, `FOUND = false` | ошибка `NO_DATA_FOUND` |
| 1 строку | значения | значения |
| > 1 строки | берётся первая (молча!) | ошибка `TOO_MANY_ROWS` |

Блок 2.4 — **ожидаемая ошибка** `query returned more than one row` (в отделе закупок 4 человека).

**Ожидаемо:** `NOTICE: Долг 6907600 руб. при лимите 3000000.00 — ЛИМИТ ПРЕВЫШЕН`

## Часть 4. Динамический SQL

### Шаг 11. `EXECUTE format()`

```sql
EXECUTE format('SELECT COUNT(*) FROM %I.%I', 'pitanie', v_tab) INTO v_cnt;
```

| Спецификатор | Назначение | Пример результата |
|---|---|---|
| `%I` | идентификатор (имя таблицы/столбца) | `orders`, `"Order Items"` |
| `%L` | литерал (значение) | `'Вектор'`, `NULL` |
| `%s` | подстановка «как есть» — **опасно** для пользовательского ввода | |

**Ожидаемо (блок 5.1):** `orders: 4458`, `order_items: 17576`, `production_batches: 6062`, `equipment_downtime: 282`.

### Шаг 12. Параметры через USING

Блок 5.2: значения передаются как `$1, $2` через `USING` — без склейки строк и без проблем с типами.
**Ожидаемо:** `Позиций со скидкой > 10 % у менеджера 10: 4312`

### Шаг 13. SQL-инъекция

Блок 5.3: «имя клиента» от пользователя — `Вектор' OR '1'='1`.

```text
NOTICE: Склейка:  SELECT COUNT(*) FROM pitanie.customers WHERE customer_name = 'Вектор' OR '1'='1'
NOTICE:   → вернулось строк: 73 (все клиенты!)
NOTICE: format %L: SELECT COUNT(*) FROM pitanie.customers WHERE customer_name = 'Вектор'' OR ''1''=''1'
NOTICE:   → вернулось строк: 0
```

> **Правило.** Имена объектов — только через `%I` (и лучше — проверка по белому списку/каталогу), значения — через `USING` или `%L`. Никогда `'...' || v_input || '...'`.

Блок 6.2:


## Шпаргалка T-SQL → PL/pgSQL

| T-SQL | PL/pgSQL |
|---|---|
| `DECLARE @x INT = 5;` | `DECLARE x int := 5;` (в блоке `DO`/функции) |
| `SET @x = 10;` / `SELECT @x = col FROM ...` | `x := 10;` / `SELECT col INTO x FROM ...` |
| `PRINT 'текст'` | `RAISE NOTICE 'текст %', x;` |
| `IF ... BEGIN ... END ELSE ...` | `IF ... THEN ... ELSIF ... ELSE ... END IF;` |
| `WHILE ... BEGIN ... END` | `WHILE ... LOOP ... END LOOP;` |
| `BREAK` / `CONTINUE` | `EXIT` / `CONTINUE` (+ метки `EXIT lbl`) |
| курсор + `FETCH NEXT` | `FOR r IN SELECT ... LOOP` |
| `BEGIN TRY ... END TRY BEGIN CATCH ... END CATCH` | `BEGIN ... EXCEPTION WHEN ... THEN ... END;` |
| `ERROR_NUMBER()`, `ERROR_MESSAGE()` | `SQLSTATE`, `SQLERRM`, `GET STACKED DIAGNOSTICS` |
| `THROW 50001, 'msg', 1;` / `RAISERROR` | `RAISE EXCEPTION 'msg' USING ERRCODE = 'P0001';` |
| `EXEC sp_executesql @sql, N'@p INT', @p = 1` | `EXECUTE format(...) USING p;` |
| `QUOTENAME(@name)` | `format('%I', name)` / `quote_ident(name)` |

## Типичные ошибки

| Ошибка | Причина | Решение |
|---|---|---|
| `unterminated dollar-quoted string` | клиент разрезал блок по `;` | выделить весь блок и выполнить; в DBeaver — `Alt+X` |
| `column "x" does not exist` в `RAISE` | забыли кавычки у текста | `RAISE NOTICE 'текст %', x;` |
| `too few parameters specified for RAISE` | `%` в тексте без аргумента | `%%` для знака процента |
| `query returned more than one row` | `INTO STRICT` и несколько строк | уточнить WHERE или убрать STRICT осознанно |
| `case not found` | оператор `CASE` без `ELSE` | добавить `ELSE` |
| Имя переменной совпало со столбцом (`ambiguous`) | `order_id` и как переменная, и как столбец | префиксы `v_`, `p_`, алиасы таблиц |
